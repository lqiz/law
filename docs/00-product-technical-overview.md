# EvidenceVault v1.0 — 产品与技术总体拆解

## 1. 产品定位

**一句话**：本地化的职场证据固化工具，让普通劳动者能用手机完成"取证 → 固化 → 导出"全流程，产出物可直接用于劳动仲裁 / 诉讼。

**目标用户**：遭遇职场侵权（欠薪、违法解雇、职场骚扰等）的普通劳动者。

**核心价值**：
- 降低取证门槛：无需专业知识，引导式操作
- 证据司法可用：解决"时间可信 + 内容未篡改"两大证据能力要素
- 隐私安全：原始文件永不离开设备

## 2. MVP 功能范围（v1.0 严格边界）

| 功能模块 | v1.0 包含 | v2.0+ 规划 |
|---------|----------|-----------|
| 证据采集 | 拍照、录音、录像、截图导入、文件导入 | OCR 识别、实时字幕 |
| 证据固化 | 本地 SHA-256 哈希 + 可信时间戳（TSA） | 区块链存证（备选） |
| 证据管理 | 按案件分组、标签、时间线浏览 | AI 智能分类 |
| 证据导出 | 生成"证据包"（原件 + 哈希报告 + 时间戳证书） | 直接对接仲裁平台 |
| 用户引导 | 取证场景模板（欠薪、解雇、骚扰） | 法律知识库 |

**明确不做**：云端存储、社交分享、在线法律咨询、AI 法律建议。

## 4. 六大模块定义

### 4.1 采集模块 (Capture)

**职责**：通过设备硬件获取原始证据文件。

| 能力 | 实现方式 | 输出 |
|-----|---------|------|
| 拍照 | Camera API | JPEG/HEIC + EXIF |
| 录音 | Microphone API | AAC/WAV |
| 录像 | Camera + Mic API | MP4 |
| 截图导入 | Photo Library Picker | 原始图片文件 |
| 文件导入 | File Picker | 任意文件（PDF/DOC 等） |

**关键约束**：
- 采集时立即记录设备元数据（GPS、时间、设备型号、OS 版本）
- 采集完成后立即进入固化流程，不允许中间编辑

### 4.2 固化模块 (Seal)

**职责**：对证据文件生成不可篡改的数字指纹 + 可信时间证明。

**固化流程**：
```
原始文件 → SHA-256 哈希 → 拼接元数据 → 生成固化请求
                                          ↓
                              发送哈希到 RFC 3161 TSA
                                          ↓
                              获取时间戳令牌 (TST)
                                          ↓
                              本地保存 EvidenceRecord
```

**司法有效性分析**：

| 要素 | 方案 | 法律依据 |
|-----|------|---------|
| 内容完整性 | SHA-256 哈希，任何修改导致哈希不匹配 | 《电子签名法》第8条 |
| 时间可信性 | RFC 3161 可信时间戳（CA 机构签发） | 《电子数据规定》第5条 |
| 来源可追溯 | 设备指纹 + 采集元数据 | 证据三性之真实性 |

**⚠️ 法律风险提示**：
1. TSA 时间戳在中国司法实践中已有采信先例（如联合信任时间戳服务），但各地法院采信标准不一
2. v1.0 建议同时接入**国内有资质的时间戳服务**（如联合信任 TSA、国家授时中心）以提高采信率
3. 录音取证需遵守"一方知情"原则，App 应在引导中明确告知用户

### 4.3 管理模块 (Manage)

**职责**：组织和浏览已固化的证据。

- 数据结构：Case（案件）→ EvidenceItem（证据条目）→ EvidenceFile（原始文件）
- 按时间线浏览
- 按标签筛选（标签：合同、工资、沟通记录、考勤、其他）
- 搜索（按备注文本）

### 4.4 导出模块 (Export)

**职责**：生成司法可用的证据包。

**证据包结构**：
```
EvidencePackage_20260208/
├── evidence/                    # 原始证据文件
│   ├── 001_photo_20260101.jpg
│   ├── 002_audio_20260115.aac
│   └── ...
├── certificates/                # 时间戳证书
│   ├── 001_photo_20260101.tsr
│   └── ...
├── metadata/                    # 元数据 JSON
│   ├── 001_photo_20260101.json
│   └── ...
├── hash_manifest.json           # 全部哈希清单
├── chain_of_custody.json        # 证据链记录
└── verification_guide.pdf       # 验证指南（给法官/仲裁员）
```

### 4.5 引导模块 (Guide)

**职责**：针对常见场景提供取证清单和操作引导。

**v1.0 场景模板**：
1. **欠薪/克扣工资** → 建议采集：工资条截图、银行流水、劳动合同、沟通记录
2. **违法解雇** → 建议采集：解雇通知、工作群消息、考勤记录、录音
3. **职场骚扰** → 建议采集：聊天截图、录音、证人信息备忘

### 4.6 安全模块 (Security，横切关注点)

| 安全需求 | 方案 |
|---------|------|
| 本地存储加密 | SQLCipher 加密数据库 + 文件级 AES-256 加密 |
| App 访问控制 | 生物识别 / PIN 码解锁 |
| 防截屏/录屏 | 关键页面启用 FLAG_SECURE (Android) / 截屏防护 (iOS) |
| 密钥管理 | Android Keystore / iOS Keychain |
| 数据擦除 | 紧急销毁功能（不可恢复删除） |

## 5. 技术选型

| 维度 | 选型 | 理由 |
|-----|------|------|
| 跨平台框架 | Flutter (Dart) | 双端一致性、性能足够、生态成熟 |
| 本地数据库 | SQLite + SQLCipher | 加密存储、无需网络、轻量 |
| 状态管理 | Riverpod | 类型安全、可测试性好 |
| 哈希计算 | dart:crypto (SHA-256) + pointycastle | 纯 Dart 实现，无需 FFI |
| 文件加密 | AES-256-GCM（pointycastle） | 认证加密，防篡改 |
| 时间戳 | RFC 3161 TSA 客户端 | 自行实现 ASN.1 请求构造 |
| 本地存储路径 | getApplicationDocumentsDirectory | 沙箱内，卸载时随 App 清除 |

## 7. 关键风险与缓解

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| TSA 服务不可用 | 无法获取可信时间戳 | 离线模式：先本地记录，联网后补时间戳；同时记录 NTP 时间 |
| 法院不采信电子证据 | 证据被排除 | 提供详细验证指南；建议用户同步使用公证处保全 |
| 用户误删原始文件 | 证据丢失 | 加密本地备份 + 导出提醒 |
| 录音合法性争议 | 录音证据不被采纳 | App 内置合法取证提示，明确"一方知情"边界 |
| 设备被没收/损坏 | 数据丢失 | 支持加密导出到外部存储（U盘/电脑） |
